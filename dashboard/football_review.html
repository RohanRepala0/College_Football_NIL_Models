Football model review

Which football outputs are solid enough to draw insights from, how each was stress-tested, and how the weekly refresh runs in production, for the football roster market page. Tests ran — on games through week —.

What you can lean on

Before you draw insights

  1. Compare programs, not players. Program totals are tested; individual values have nothing to test against and aren't shown.
  2. Call a program's surplus only when it holds. Use the ones in surplus or deficit under all four ratings and stable under resampling; treat the rest as even.
  3. Quote ranges past the 90th percentile. The top of the market depends on how much of the cap football takes.
  4. Read NIL Go percentiles as roughly ±10 points. Revenue-share percentiles are good to about 1 to 2 points.
  5. Value positions only where they're stable: quarterback, offensive line, linebacker and running back. Defensive backs and wide receivers can't be valued from public data.
  6. Rank across FBS before ranking within a conference. Within-conference rankings are weaker, the Big 12's most of all.
  7. Read the player-score weights as production first. They are one set fit on two seasons; nearby sets fit almost as well, so the exact shares carry little meaning.
  8. Check that this week's gates passed before using a new week's numbers.

How it runs

Two scheduled jobs in the GitHub repository commit their results, and a third publishes the site to GitHub Pages after each of them. Nothing is published unless the checks pass.

Daily: College Sports Commission capture (running since October 30)

FetchThe NIL Go and revenue-share pages, and every NIL Data Report.
VersionEach payload hashed and archived; only something new is committed. A changed page layout fails the run.
CalibrateBenchmark curves and tails refit to the newest release and NIL Go totals.

Weekly, Mondays: football refresh (ready, needs one secret)

PullRosters, recruiting, portal and production, this season's games, SP+, ESPN FPI, SRS and Elo: about 23 CollegeFootballData calls.
ModelRoster market value, on-field value under each rating, surplus with ranges.
Testnil validate-football --gate: the stress tests on this page and the quality gates.
SnapshotThe week's outputs saved under data/players/history/<date> for week-over-week checks and audit.
PublishThe week's data committed; the Pages workflow rebuilds the site and deploys it to GitHub Pages.

In place

  1. Daily capture of the CSC pages and NIL Data Reports, versioned in the repository.
  2. Weekly workflow (.github/workflows/football-weekly.yml) with the gates as a hard stop.
  3. Stress tests as a command, nil validate-football, and a report in reports/football_validation.md.
  4. A GitHub Pages workflow (.github/workflows/pages.yml) that rebuilds and deploys the site after every capture and refresh.
  5. Week-by-week snapshots, starting —.
  6. Automated tests for every module, run before each job.

Needed to switch it on

  1. Add the CFBD_API_KEY secret to the repository (Settings, Secrets and variables, Actions). The weekly job stops at its first step without it.
  2. Optional: a RATINGS_REPO_TOKEN secret that can read CollegeFootballRatings2026, for the Expectations tab. Without it the job keeps last week's projections.
  3. Turn on GitHub Pages: Settings, Pages, Build and deployment, Source: GitHub Actions. The site is public, like the repository, at rohanrepala0.github.io/College_Football_NIL_Models.
  4. Name who gets failure emails. GitHub emails the repository owner when a gate or a capture fails.

Model work before wider use

  1. Add seasons as they come. The weights and position values are pooled over 2025 and 2026; each new season adds a block of team-seasons.
  2. Better defensive inputs. Public box-score stats can't tell defensive backs apart; coverage data would be needed to value them.
  3. A season of history. Weekly snapshots will show how surplus moves as games are played, and whether pre-season market value predicts the final ratings.
  4. Reported deals as a check. A ledger of reported contracts, run through the credibility tests, would be the first outside check on program market values.
